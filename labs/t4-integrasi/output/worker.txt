# --- B. Dengan breaker per lajur; vendor tetap menggantung: lajur verifikasi dijeda, pemberitahuan uang tidak menunggu ---
$ ./api-t4 -peran worker -serentak 4 -backoff 1ms -selang 50ms -breaker -breaker-timeout 30s
# Dua putaran menggantung (8 percobaan, 3 detik tiap putaran) membuka breaker. Percobaan per pekerjaan:
=> SELECT status, percobaan, count(*) AS jumlah FROM outbox WHERE tujuan = 'verifikasi' GROUP BY status, percobaan ORDER BY status, percobaan

----------+-----------+--------

(2 rows)
# breaker terbuka: 8 permintaan masuk, 0 objek dibuat (kunci berbeda = objek berbeda)
# Budi membayar empat kali Rp1.000 ke Warung Ani:
# Keempat pemberitahuan sampai di layanan push kurang dari 2,0 detik sesudah dibayar (batas atas diperiksa; nilainya tidak direkam).
=> SELECT status, percobaan, count(*) AS jumlah FROM outbox WHERE tujuan = 'verifikasi' GROUP BY status, percobaan ORDER BY status, percobaan

----------+-----------+--------
 menunggu | 0         | 4
 menunggu | 2         | 4
(2 rows)
# Lajur verifikasi tetap dijeda: tidak ada permintaan baru ke vendor dan percobaan tidak bertambah.
