# Brief subagen mode penyelesaian penuh

Dibaca subagen pelaksana dan peninjau di setiap tugas Tahap 2–6 (keputusan 559, 727, 728). Pengatur menyebut di brief: id tugas, worktree, branch, port, rentang nomor keputusan, bagian naskah, batas waktu. Urutan aturan: CLAUDE.md > PROTOKOL-OTOMATIS.md > skill > prompt pemilik mode penuh > MEMORI.

Baris pembuka setiap brief: "Baca CLAUDE.md, PROTOKOL-OTOMATIS.md, dan skill yang relevan sebelum mulai; laporkan skill mana yang dipakai." Laporan tanpa daftar skill dianggap belum selesai.

## Yang berlaku untuk keduanya

- CLAUDE.md seluruhnya: `<commit>` (commit otomatis per perubahan utuh, pesan bahasa Indonesia kata kerja di depan dengan nomor keputusan, tanpa trailer Co-Authored-By, tanpa nama alat AI, tanpa emoji, tanpa force-push, branch `tahap-N/<slug>`), `<tampilan>`, `<gerbang_kualitas>`, `<larangan>`.
- PROTOKOL-OTOMATIS.md bagian c–g dan k (hemat konteks: output ke file lalu `tail`/`grep`; file > 300 baris dibaca per rentang; paling banyak dua tangkapan dibuka per tugas, HP dulu).
- ANTREAN "Definisi selesai bersama" termasuk paragraf "Mode penyelesaian penuh".
- Skill: gaya-bahasa (semua teks pembaca), visualisasi (widget, diagram, ilustrasi, layout), analisis-kritis (klaim, ADR ≥ 3 opsi + pre-mortem + kapan salah, pemilihan library, review kode), riset-tahap (riset, klaim baru), evaluasi-tahap (evaluasi).
- Sumber kebenaran: `plan/CERITA-TAHAP-N.md` untuk tahap itu (Tahap 1–2 milik pemilik, tidak diubah; usulan ke laporan), PROPOSAL.md untuk tech stack, desain visual, dan keamanan, RINGKAS.md sebagai peta, `plan/RISET-TAHAP-N.md` sebagai jejak klaim (ID `RN-nn`).
- Label kejujuran di setiap angka dan output: Rekaman lab, Ilustrasi, Tidak dijalankan, Asumsi, [perlu verifikasi].
- Pemilik tidak ditanya. Keputusan yang biasanya ditanyakan: ambil opsi paling aman dan paling mudah dibatalkan, catat di KEPUTUSAN (nomor dari rentang di brief), dan tulis di laporan baris "Diputuskan tanpa pemilik".
- BERKAS BERSAMA (keputusan 727, berlaku untuk tugas yang dibuka sejak 2026-10-25): halaman dan lab TIDAK mengubah `plan/ANTREAN.md`, `plan/MEMORI.md`, `plan/STATUS.md`, `plan/KEPUTUSAN.md`, `plan/SETELAH-TAHAP-N.md`, `plan/masuk/`, dan tidak menulis `jalur_inti` (tidak disimpan lagi di cerita.json). Pengatur yang mengubahnya, lewat PR catatan per 3 halaman (`python3 tools/ambil_catatan_pr.py <PR...>` mengambil `### KEPUTUSAN` dan `### SETELAH-TAHAP-N` dari badan PR ke file masuk, lalu `python3 tools/lipat_masuk.py`). Catatan yang sebelumnya ke file masuk ditulis di BADAN PR, bagian akhir `## Catatan pengatur` dengan sub-bagian: `### KEPUTUSAN` (baris tabel TEPAT 5 kolom `| n | tanggal | apa | kenapa | alternatif |`, sumber di dalam kolom, pipe di teks `\|`, nomor dari rentang di brief), `### SETELAH-TAHAP-N` (polesan satu baris, diawali `- `), `### PERLU-DICEK-PEMILIK`, `### USULAN-CERITA`, `### DIPUTUSKAN-TANPA-PEMILIK`, `### ISTILAH-BARU`, dan `### REGISTRI` (perubahan registri yang kamu butuhkan di luar entri halaman sendiri). Yang tetap di PR halaman karena CI mewajibkannya cocok: berkas halaman, data widget, halaman istilah baru, entri registri halaman itu sendiri (`ada`/`lebur_ke`), dan turunan hasil `sinkron_cerita.py`/`build_istilah.py`. `plan/RISET-TAHAP-N.md` hanya menambah baris ID riset milikmu.
- TIGA LAJUR (keputusan 728, menggantikan batas dua PR di 727): sampai tiga PR halaman terbuka bersamaan, tiap lajur di worktree sendiri (`rjt-*`). Rujuk halaman tetangga lewat ID registri `[[ID]]` dan jangan menunggu tetangga merge. Lab paralel: brief menyebut `COMPOSE_PROJECT_NAME`, `LAB_DB_PORT`, dan `LAB_PORT_OFFSET` lajurmu; pakai persis itu (bawaan tanpa variabel tetap port 54333, bila LAB-PARALEL belum merge). Lajur lain boleh mereset database lab di lajurnya sendiri, tidak di lajurmu.
- LAJUR LAB (keputusan 860–864, tabel dari PR #326; variabel `COMPOSE_PROJECT_NAME`, `LAB_DB_PORT`, `LAB_REDIS_PORT`, `LAB_PORT_OFFSET`; cara pakai di `labs/README.md` "Beberapa lajur sekaligus"): rjt-konten kosong/54333/56379/0 (bawaan, container `b3-race-db-1`); rjt-konten2 `rjt-konten2`/54433/56479/100; rjt-konten3 54533/56579/200; rjt-teknis 54633/56679/300; rjt-teknis2 54733/56779/400; rjt-teknis3 54833/56879/500; rjt-konten4 54933/56979/600; port replika t5-replika 54640/54641 + offset. Nama proyek compose = nama worktree. Jangan menyentuh, mereset, atau `down` proyek bawaan; hentikan hanya proyek lajurmu. Lab yang berbagi port dasar tidak bisa jalan serentak dalam satu lajur.
- JARINGAN dan SHELL (pelajaran 2026-10-25): koneksi ke GitHub kadang putus (graphql broken pipe, read tcp): ulangi perintah `gh`; `gh pr checks` yang gagal karena jaringan bukan CI gagal; JANGAN hapus branch remote atau anggap merge berhasil sebelum `gh pr view <n> --json state -q .state` = MERGED (PR tertutup bila branch dihapus lebih dulu). Shell sesi adalah zsh: `set -- $var` tidak memecah kata, tulis loop di skrip `bash`. Sebelum menutup daftar halaman "segera", cari tes yang bergantung pada keadaan itu (`situs/src/erd/tumbuh.test.ts`). Gabung konflik dua sisi yang sama-sama menambah blok JSX/objek: jalankan `bun run --cwd situs build` SEGERA. Jalankan yang murah dulu: `node --test tests/widgets/*.cjs`, `python3 tools/sinkron_cerita.py --check`, `python3 tools/audit_bahasa.py --check <berkas plan>` (gerbang tidak memeriksa teks `plan/`); hapus `tmp/cek-hasil.txt` lama sebelum gerbang di latar. Halaman dengan angka wajib punya penjaga angka (contoh `situs/src/widgets/selisih-bank/halaman.test.ts`, `kunci-akun`, `job-rekonsiliasi.halaman.test.ts`): uji mutasi mengubah satu angka dan tes harus gagal. Tabel widget tidak boleh meluap di 320 px (WCAG 1.4.10).
- Lab: hanya container lokal; pihak ketiga selalu tiruan lokal; rekaman dari database bersih, diulang dan dibandingkan (status, saldo, urutan; bukan waktu); lab gagal keras bila hasil meleset. Venv lab: symlink `labs/.venv` ke folder utama bila belum ada.
- Worktree baru: `bun install --cwd situs` dan font (`bash tools/get_fonts.sh`) sebelum gerbang. Gerbang: `bash tools/cek_situs.sh --layar > tmp/cek.txt 2>&1 && echo LOLOS || echo GAGAL` lalu `tail -30 tmp/cek.txt`, dengan `PORT_PREVIEW` dari brief. PR yang hanya mengubah `plan/` atau skill boleh memakai gerbang tanpa `--layar`; CI tetap menjalankan semuanya.
- CI: tunggu dengan `gh pr checks <n> --watch --interval 60` (timeout 1200); putusan akhir dari `gh pr checks <n>` tanpa --watch (harus keluar 0). Job gagal di langkah "Pasang Chromium Playwright" dengan exit 124 berarti mirror apt lambat: `gh run rerun <run-id> --failed`, bukan perbaikan kode. Kelompok ukur CI kini empat job ("layar judul ilustrasi rantai axe race", "gerak", "erd", "diagram cls kontras luapan alur", batas langkah 13 menit); run push di main tidak dibatalkan (keputusan 726, 727).
- Sebelum melapor: hentikan semua proses latar milikmu (watch CI, preview), dan sesudah melapor jangan menyentuh worktree lagi; worktree itu segera dipakai tugas lain.
- ATURAN MERGE peninjau (keputusan 727, menggantikan aturan ancestor): PR yang `mergeable` = MERGEABLE (poll `gh pr view <n> --json mergeable` sampai bukan UNKNOWN) dan tidak menyentuh file yang sama dengan PR terbuka lain boleh di-merge TANPA menggabung main lebih dulu, asalkan CI PR hijau; CI main adalah jaring pengaman. Bila bentrok atau menyentuh file yang sama dengan PR lain: `git merge origin/main`, file turunan registri (cerita.json) ambil dari main lalu `python3 tools/sinkron_cerita.py` dan `python3 tools/build_istilah.py`, RISET urut ID, `node --test`, cek rentang Snippet, push, CI ulang. Sesudah merge: lihat run CI main untuk merge itu; bila MERAH: jangan merge apa pun lagi, lapor ke pengatur (revert dan parkir seperti PROTOKOL-OTOMATIS f dan g.6). Mulai jam PR dibuka dan jam merge dicatat di laporan. Tanpa gerbang penuh sesudah merge: run CI main untuk merge itu menggantikannya (keputusan 728).
- Jangan `pkill -f` berpola (mis. `cek_situs.sh --layar`): mematikan gerbang worktree lain. Kenali PID gerbangmu lewat `lsof -d cwd` dan hentikan PID itu saja. Edit teks lewat skrip Python di `tmp/`, jangan `sed -i` di macOS. Nomor keputusan dan ID riset dari brief wajib dicek lawan KEPUTUSAN dan semua PR terbuka sebelum dipakai (insiden 2.18 dan 2.17).
- Batas waktu: halaman, lab, widget 120 menit; lainnya 75 menit. Lewat batas: commit yang aman, push, laporkan "lanjutkan nanti" dengan langkah berikutnya.

## Pelaksana

1. Baca blok tugas di ANTREAN, bagian naskah yang disebut, halaman tetangga, tes yang menyentuhnya, dan baris RISET-TAHAP-N yang relevan.
2. Branch dari `origin/main` terbaru di worktree dari brief. Kerjakan sesuai "selesai bila".
3. Gerbang penuh dijalankan SEKALI di sini sebelum PR dibuka (keputusan 728); lolos, push, `gh pr create` (isi: apa yang berubah, apa yang dicek dengan potongan output, tiga pertanyaan navigasi untuk halaman, skill yang dipakai, apa yang belum, dan akhir `## Catatan pengatur` seperti di BERKAS BERSAMA; halaman diakhiri "Siap dilanjutkan dari <nomor>"), tunggu CI sesuai aturan CI di atas. Bila main bergerak dan PR-mu tidak bentrok, jangan menggabung main.
4. JANGAN merge. Kembalikan tepat 6 baris: status, PR, keputusan (nomor + frasa), hal untuk pemilik (Perlu dicek pemilik / Usulan perubahan cerita / Diputuskan tanpa pemilik, atau "-"), satu pelajaran, skill yang dipakai; baris 1 memuat jam mulai tugas, jam PR dibuka, dan jumlah commit "Gabungkan origin/main" di PR-mu (bahan ukur keputusan 727 dan 728).

## Peninjau

1. Kamu tidak menulis tugas ini. Baca diff ke file (`gh pr diff <n> > tmp/pr.diff`), lalu bagian yang perlu.
2. Periksa terhadap "selesai bila", naskah, Definisi selesai bersama, CLAUDE.md, dan skill. Wajib: TIDAK mengulang gerbang penuh (pelaksana menjalankannya sekali, CI menjalankannya lagi; keputusan 728), tetapi baca diff, rekaman, dan rujukan; ulang lab dari database bersih bila PR mengubah lab atau rekamannya, bila tidak cocokkan angka halaman dengan rekaman; uji mutasi untuk lab dan kode (ubah satu hal, pastikan tes atau lab gagal, kembalikan); untuk halaman buka dua tangkapan (375×667 dulu) dan jawab tiga pertanyaan navigasi; cek tiga klaim acak ke sumbernya (ID riset atau rekaman); baca kode untuk yang tidak ada (validasi hilang, kasus gagal, retry tanpa batas).
3. Temuan kategori rusak, aksesibilitas, kontras, gerbang gagal, atau klaim salah: perbaiki sendiri di branch yang sama (commit terpisah) dan tulis keputusan barunya di badan PR (`## Catatan pengatur`, nomor dari rentang di brief); PR yang dibuka sebelum 2026-10-25 yang sudah punya file di `plan/masuk/` menambahkan ke file itu. Polesan: satu baris di `### SETELAH-TAHAP-N` badan PR.
4. Sesudah perbaikan: gerbang ulang, push, CI hijau (aturan CI dan ATURAN MERGE di atas), lalu `gh pr merge <n> --merge` (tanpa --delete-branch bila worktree lain memegang main) dan `git push origin --delete <branch>`; sesudah merge periksa run CI main untuk merge itu.
5. Kembalikan tepat 6 baris (baris 1 juga menyebut menit CI PR dan jumlah jeda limit yang kamu alami): status (merge / perlu pelaksana / diparkir), PR, temuan dan perbaikannya, keputusan, hal untuk pemilik, skill yang dipakai.
